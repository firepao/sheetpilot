## 关键陷阱

### 陷阱1: 维度数量不足

❌ **错误1**: 只用月份维度
```json
"dimensions": [
  {"id": "month", "field": "月份", ...}
]
```
会丢失年份和季度信息

❌ **错误2**: 只用2个维度
```json
"dimensions": [
  {"id": "year", "field": "年份", ...},
  {"id": "month", "field": "月份", ...}
]
```
会丢失季度信息

✅ **正确**: 必须包含3个维度

### 陷阱2: 维度顺序错误

用户说"按年份、季度、月份统计" → 顺序很重要

❌ 错误顺序：
```json
"dimensions": [
  {"id": "month", ...},   // 月份在前
  {"id": "quarter", ...},
  {"id": "year", ...}
]
```
输出会变成先按月份分组（所有年份的1月在一起）

✅ **正确顺序**:
```json
"dimensions": [
  {"id": "year", ...},     // 年份在前
  {"id": "quarter", ...},
  {"id": "month", ...}
]
```

**理解**: dimensions的顺序决定分组的优先级（从粗到细）

### 陷阱3: 遗漏acceptance维度

❌ 错误：
```json
"dimensions": [
  {"id": "year", ...},
  {"id": "quarter", ...},
  {"id": "month", ...}
],
"acceptance": {
  "required_dimensions": ["year", "month"]  // 遗漏了quarter
}
```

✅ 正确：
```json
"acceptance": {
  "required_dimensions": ["year", "quarter", "month"]
}
```

### 陷阱4: 误用字符串拼接
Agent可能尝试构造"2024-Q1-1月"这样的复合维度 → **超出能力范围**

SheetPilot不做字段转换，只能使用原始字段

## 多维度分组理解

**单维度（S2）**:
```
华东 → 230000
华南 → 200000
```

**双维度（S7）**:
```
华东-电子产品 → 85000
华东-家居用品 → 62000
华南-电子产品 → 72000
华南-家居用品 → 58000
```

**三维度（H5）**:
```
2024-Q1-1月 → 82000
2024-Q1-2月 → 78000
2024-Q1-3月 → 85000
2024-Q2-4月 → 90000
...
```

## 学习要点

**对于Agent开发者**:
1. dimensions的**顺序**决定输出的分组层级
2. 层级关系应该从粗到细（年→季→月，不是月→季→年）
3. 3个维度都要加入acceptance的required_dimensions
4. 层级汇总验证：下层求和应等于上层（3个月=1个季度）

**对于Oracle设计者**:
1. 验证点应包括层级汇总（如Q1=1月+2月+3月）
2. 提供"如果顺序错误的预期结果"作为对比
3. 时间维度特别适合测试层级分组

**对于Runtime**:
- dimensions顺序会影响输出行的排序
- 不做跨维度的汇总（如自动生成季度小计行）
- 每个唯一的(维度1, 维度2, 维度3)组合生成一行
