# R6: 物流配送时效分析（真实场景）

## 场景描述
物流配送时效监控场景，统计各区域的超时情况。包含真实数据特征：18%超时率（符合行业水平）。

## 测试目标
- 验证大数据量场景（3000行运单）
- 验证字符串相等过滤（是否超时='是'）
- 验证时效分析业务逻辑
- 验证物流领域关键指标

## 输入文件
- **文件路径**: `tests/agent_contract/data/R6_logistics_timeout.xlsx`
- **工作表**: `配送记录`
- **表头行**: 1
- **数据特征**: 
  - 3000行运单记录
  - 8个配送区域（北京、上海、广州、深圳、杭州、成都、武汉、西安）
  - 超时率：约18%（540条超时 / 3000条总运单）
  - 承诺时效：24h/48h/72h三档
  - 发货时间：2026年1月-6月

## 用户需求（Prompt）

```
请分析配送记录，统计各区域的超时订单情况。

要求：
- 只统计超时订单（是否超时='是'）
- 按配送区域分组
- 计算各区域的：
  1. 超时订单数量
  2. 该区域总订单数量（需要单独统计）
  3. 超时率（超时订单数 / 总订单数）
- 按超时率降序排列

注意：超时率需要基于该区域全部订单计算，不仅是超时订单。

输入文件: tests/agent_contract/data/R6_logistics_timeout.xlsx
输出文件: <由Agent决定>
```

## 预期执行流程

1. **查询字段清单**
   ```bash
   sheetpilot task-types --input tests/agent_contract/data/R6_logistics_timeout.xlsx --sheet 配送记录 --header-row 1
   ```

2. **理解需求的跨过滤聚合问题**
   - 指标1：超时订单数（过滤：是否超时='是'）
   - 指标2：总订单数（无过滤）
   - 指标3：超时率 = 指标1 / 指标2（派生计算）
   
   **问题**: SheetPilot当前Task API要求过滤条件对所有指标生效，无法支持"部分指标过滤、部分指标不过滤"
   
   **预期Agent行为**: 
   - 发现需求超出能力边界
   - 返回 `CAPABILITY_UNSUPPORTED` 或提出简化方案

3. **简化方案A（如Agent提出）**
   只统计超时订单：
   - 过滤条件: `是否超时 = 是`
   - 维度: `配送区域`
   - 指标: `count.rows` → `超时订单数`
   - 说明: 总订单数和超时率需人工二次计算

4. **简化方案B（如Agent提出）**
   输出全量区域汇总（无过滤）：
   - 维度: `配送区域` + `是否超时`
   - 指标: `count.rows` → `订单数`
   - 说明: 人工Pivot或二次处理得到超时率

5. **提交任务**
   ```bash
   sheetpilot task-run --request request.json --auto-result-dir <result-dir>
   ```

6. **复核状态**
   ```bash
   sheetpilot task-status --task-id <task-id>
   ```

## 真实性体现

2. **超时率**: 18%（符合快递行业正常水平，顺丰约5%，通达系约15-20%）

## 关键点
- ⚠️ **能力边界**: 当前Task API不支持跨过滤聚合（部分指标过滤，部分不过滤）
- ✅ **正确处理**: 识别超出能力，提出简化方案（分两次查询或输出原始分组）
- ❌ **错误处理**: 强行只输出超时订单，未说明超时率无法直接计算

## 业务洞察
- **超时率**: 物流服务质量核心指标
- **区域差异**: 西部城市（西安、成都）超时率略高（路途远、支线物流差）
- **优化方向**: 超时率>20%的区域需重点优化（增加中转站、调整路由）

## 扩展场景
