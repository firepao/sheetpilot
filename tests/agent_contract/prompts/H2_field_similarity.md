# H2: 字段名相似性陷阱

## 场景分类
- **难度**: Hard
- **系列**: H (Hard) - 复杂场景验证
- **测试重点**: 相似字段名的精确识别

## 数据文件
- **路径**: `tests/agent_contract/data/H2_number_format.xlsx`
- **工作表**: `销售记录`
- **数据量**: 约95行
- **表头行**: 第1行

## 表头结构（陷阱密集）
| 列名 | 数据类型 | 说明 |
|------|---------|------|
| 员工编号 | 文本 | E0001-E0095 |
| 部门 | 文本 | 销售部/研发部/财务部 |
| 基本工资 | 数值 | 基础工资 |
| **实发工资** | 数值 | 实际到手工资（扣除五险一金后） |
| **应发工资** | 数值 | 税前工资 |
| 工资 | 数值 | 岗位工资（基本工资的组成部分） |
| 绩效工资 | 数值 | 绩效奖金 |

## 数据特殊性

**关键挑战**: 5个包含"工资"的字段名，语义容易混淆：
1. `基本工资` - 基础工资（不含绩效）
2. `工资` - 岗位工资（基本工资的一部分）
3. `绩效工资` - 绩效奖金
4. `应发工资` - 税前总额（基本+绩效）
5. `实发工资` - 实际到手（应发-五险一金） ⚠️ **最终金额**

**关系**:
- 工资 ⊂ 基本工资
- 应发工资 = 基本工资 + 绩效工资
- 实发工资 = 应发工资 - 扣除项

## 用户需求（Prompt）

```
请统计每个部门的平均工资。

输入文件：tests/agent_contract/data/H2_field_similarity.xlsx

```

## 歧义分析

用户说的"平均工资"可能指：
1. `实发工资` ✅ **最常见理解**（HR、员工关心的实际收入）
2. `应发工资` ❌（财务口径，包含扣除项）
3. `基本工资` ❌（不含绩效）
4. `工资` ❌（只是岗位工资）

**Oracle设计**: 本场景认为"平均工资"=`实发工资`平均值

## 关键陷阱

### 陷阱1: 选择错误的字段名

❌ **常见错误1**: 使用"工资"
```json
{"field": "工资", ...}
```
"工资"只是岗位工资，数值明显偏小

❌ **常见错误2**: 使用"应发工资"
```json
{"field": "应发工资", ...}
```
应发工资是税前，比实发高

❌ **常见错误3**: 使用"基本工资"
```json
{"field": "基本工资", ...}
```
基本工资不含绩效，不是实际收入

✅ **正确**:
```json
{"field": "实发工资", ...}
```

### 陷阱2: 字段名模糊匹配
Agent可能认为：
- "平均工资" ≈ "工资" ❌（字面相似但语义不同）
- "平均工资" ≈ "基本工资" ❌（包含"工资"但不是最终金额）

**正确理解**: 
- "平均工资"在HR语境下默认指"实发工资"

### 陷阱3: 绑定时选错候选
如果触发`NEEDS_BINDING`，Agent看到候选列表：
```json
"field_inventory": [
  {"header": "工资", "sample_values": [5000, 6500, ...]},
  {"header": "实发工资", "sample_values": [9200, 11500, ...]},
  {"header": "应发工资", "sample_values": [10000, 12500, ...]}
]
```

**判断依据**:
- "实发工资" < "应发工资" ✓（合理）
- "实发工资" > "工资" ✓（合理）
- 名称包含"实发"暗示是最终金额

## 字段名相似度陷阱总结

| 字段名 | 包含"工资" | 数值范围 | 是否正确 |
|--------|-----------|---------|---------|
| 工资 | ✓ | 5000-7000 | ❌ 太小 |
| 基本工资 | ✓ | 7000-9000 | ❌ 不含绩效 |
| 绩效工资 | ✓ | 2000-4000 | ❌ 只是奖金 |
| 应发工资 | ✓ | 10000-13000 | ❌ 税前 |
| 实发工资 | ✓ | 9000-12000 | ✅ **正确** |

## 学习要点

**对于Agent开发者**:
1. 字段清单中字段名的细微差别很重要
2. "XX工资"不等于"工资"，要看完整字段名
3. 样本值可以辅助判断（实发 < 应发）
4. 业务常识：HR语境下"工资"默认指实发

**对于Prompt设计者**:
1. 故意设置相似字段名测试精确匹配能力
2. 提供样本值帮助Agent区分
3. Oracle标准应明确指定正确字段

**对于Runtime开发者**:
1. 字段绑定应该是精确匹配，不做模糊匹配
2. 字段清单的样本值很重要（帮助语义判断）
