# 统计类测试集评估

## 路径规范

所有场景 Prompt 中的输入文件统一使用相对于项目根目录的路径：

`tests/agent_contract/data/<文件名>.xlsx`

该目录下的文件名由场景 JSON 的 `data_file` 字段决定。输出文件继续使用运行时生成目录占位符，不把结果写死到用户机器上的固定目录。

## 当前规模

当前注册表共有 26 个 active 场景，均通过场景注册校验。重复的 5 个统计场景及其源数据已直接移除；后续新增能力应新增独立数据集，不再复用这些已删除样本。

| 类别 | 场景数 | 主要统计结构 |
|---|---:|---|
| S 简单 | 9 | 单维度求和、计数、平均值、单/多条件过滤、双维度、多指标 |
| M 中等 | 8 | 多维度、多指标、过滤后汇总、排序、去重 |
| H 困难 | 5 | 日期识别、字段消歧、复杂过滤、三维统计 |
| R 真实业务 | 6 | 对账、库存预警、薪资、客户分层、ROI、物流时效 |
| E/N/I 集成业务 | 3 | 保留工作簿对象的复杂经营汇总与清洗分析 |
| **合计** | **26** | |

其中 S/M/H/R 的 23 个场景是直接统计测试；E/N/I 的 3 个场景虽然测试重点包含文件保真、清洗和写回，但核心仍是筛选、分组、计数、求和或平均值。

## 重复度判断

结论：**统计测试集偏多**。本次已删除 5 个同构统计场景，重复主要集中在“同一聚合算子换一份业务数据”。

高重复组：

- `S1_department_sales` 与 `S2_single_dim_metric`：单维度求和 + 排序，保留一个作为最小求和基线即可。
- `S3_count_rows` 与 `S4_count_non_empty`：都验证计数，但分别覆盖行数计数和非空计数，两个语义应保留；不应合并成一个普通 count。
- `S5_average`：单独覆盖平均值和空值处理，可保留。
- `S6_single_filter` 与 `S9_multi_filter`：分别覆盖单条件和多条件过滤，建议保留一个基线、一个组合场景。
- `S7_two_dims` 与 `S8_multi_metrics`：分别覆盖多维分组和多指标输出，结构互补，但可将其中一个降为参数变体。
- M 系列与 R 系列：大量复用“过滤 + 分组 + sum/count/average”，差异主要来自业务规则和脏数据；不宜全部作为独立统计基线重复计分。

## 建议的数据集分层

具体精简结果已落在 `tests/agent_contract/default_execution_manifest.json`：

| 层级 | 建议数量 | 用途 |
|---|---:|---|
| 原子冒烟集 | 8 | 每个核心语义一个代表：sum、count rows、count non-empty、average、filter、sort、multi-dimension、multi-metric |
| 分子回归集 | 10 | 保留 M/R 中业务规则真正不同的场景，如对账、库存预警、ROI、超时率、去重、脏数据 |
| 高难边界集 | 5 | 日期歧义、字段歧义、复杂条件、三维分组、空值/异常值 |
| 集成保真集 | 3 | E2、N1、I3，验证原工作簿对象保留和结果写回 |
| **默认执行建议** | **26** | 其余场景作为参数化扩展或夜间全量回归 |

这样将源数据集固定为 26 个执行 case，删除 5 个同构统计样本，降低后续维护和评估成本，同时保留核心原子语义和真实业务差异。新增能力应新增独立数据集，避免重新把多个能力塞进同一统计样本。

## 后续收敛规则

若两个场景的输入字段类型、过滤谓词、分组维度、指标函数、排序方式和验收条件完全一致，则只保留数据质量更复杂或覆盖行数更大的场景作为默认 case；另一个场景转为参数变体。只有当场景引入新的原子语义、业务规则、数据质量问题或工作簿保真要求时，才继续作为独立测试。
